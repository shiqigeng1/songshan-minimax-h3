# H3 时间嵌入 FP32 SiLU 九齿实验

算子来源为 InfiniLM `minimax_h3` 固定提交的 `MiniMaxH3TimeEmbedder::forward`。该模块的两层 Linear 明确采用 FP32，中间调用 SiLU；实际隐藏维度由官方配置给出为 5376。本实验保持该处的实际精度，未改模型权重或生成配置。

## 复现

在现有 Pod 内运行，`WORK_HOME` 指向持久化账号主目录：

```bash
bash "$WORK_HOME/Projects/h3_ops/run_silu.sh" \
  > "$WORK_HOME/logs/h3-silu-run.log" 2>&1
cat "$WORK_HOME/Projects/h3_ops/results/silu.status"
```

`COMPLETE` 表示原生与九齿正确性、原生 A / 普通九齿 JIT / 九齿执行计划 / 原生 B 的串行基准均完成。失败会保留日志并停止，不生成成功报告。

主要代码：`silu_nt.py`。测试与计时：`benchmark_silu.py`。全部模型数值计算在九齿 arrangement/application 中表达；Torch 在算子入口只用于分配、视图和宿主元数据，测试中用于输入与参考值。

只支持连续二维 FP32 输入输出。`prepare(x, out=out)` 先执行正常九齿编译及指针验证，再将稳定存储、形状、设备和流绑定到编译器提供的 C 宿主启动器，避免重复查询指针和构建包装；每次仍执行完整 SiLU。可以原地更新输入内容；更换存储、形状、流或插桩配置后需重新准备。准备要求单线程，当前使用固定 NineToothed/Triton 版本的内部宿主接口。张量、流及生成二进制的生命周期由计划保留。需要临时空间、协作启动或插桩回调时保留正常启动路径。

原生和九齿使用不同 venv 的独立进程，避免 ntops 自动切换原生分派；所有数值工作和基准均在 Pod 中执行。

## 读结果

- 正确性分别与 Torch 和同输入原生输出直接比较；容差 atol=rtol=1e-5。验证另会改变原地址输入并再次执行，避免误把结果缓存作为优化。
- 5376 是模型真实结构宽度，257 用于尾部掩码验证；测试行数和输入数值为构造覆盖，未声称已采集完整 H3 的形状分布。
- 每例预热 40 次；11 轮、每轮 300 次，轮次起止设备同步。单位是包含宿主分派和设备完成的批量墙钟时间/次，不能解释为纯设备内核延迟。
- 分配、输入生成、JIT、执行计划准备不计入稳态，准备耗时另存。原生张量包装也在计时外完成。
- 各后端统一将 Torch CPU/interop 线程设为 1，避免输入生成线程池触发 7 核 Pod 的 CPU 配额抖动。
- 原始 JSON、A/B 漂移和慢于原生的情况均保留；性能只是单算子结果，完整视频尚未生成。

时间步编码及低精度 SwiGLU 的失败草稿没有接入这个实验，也不应作为成功成果。完整 H3、质量评测、多卡和正式 C++ 调用集成都属于后续阶段。
